Federated profile architecture

One provider tree. Two React generations.

The Host direct-loads a React 19 adapter from the profile-ui project. That adapter consumes CopilotKit in the shared Host tree, then bridge-loads the existing React 18 Profile feature and reads only its plain { context, handler } integration.

Profile tool round trip

The adapter is the only layer that knows both sides: CopilotKit above and the plain legacy integration below.

  1. 1

    Agent requests an update

    Chat and the Host core call the runtime; the agent emits the Profile frontend tool.

    update_financial_profile
  2. 2

    Adapter dispatches

    The React 19 registration reads the latest legacy handler from a stable ref.

    integrationRef.current.handler
  3. 3

    Plain call crosses the bridge

    Only update arguments and a JavaScript function call enter the React 18 boundary.

    handler(updates)
  4. 4

    Legacy state changes

    React 18 validates fields, updates owned state, recalculates the summary, and rerenders.

    setFinancialProfile(...)
  5. 5

    Fresh context returns

    The legacy feature republishes its integration; the adapter replaces the Profile context in CopilotKit.

    onProfileIntegrationChange(...)
Host owns platform concerns Provider, browser core, router, runtime connection, and outer remote boundary.
Adapter owns CopilotKit concerns Profile context/schema/tool registration, integration ref, and nested bridge lifecycle.
Legacy owns domain concerns Financial state, calculations, UI, validation, and mutation handlers remain in React 18.
Profile stays mounted when hidden, preserving React 18 state and active registrations. Key contract: onProfileIntegrationChange({ context, handler })
